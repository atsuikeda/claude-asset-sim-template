# 毎日の使い方

**やることは「成績と日報を読む」だけです。** 売買の判断は Claude が行い、ルールの番人（`sim.py`）が記録します。

## 成績の読み方（REPORT.md）

運用を始めると、`REPORT.md` が毎回自動で書き換わります。読む場所は3つです。

1. **一番上の表** — 「Claude の運用」と「オルカン相当を買って放置」の評価額と増減。ここが一番大事です。Claude のほうが上なら、判断が役に立っています。
2. **「差」の行** — たとえば「差: -2.15 ポイント」なら、Claude の運用のほうが2.15ポイント負けています。**数日〜数週間の差は、ただの偶然のことが多い**です。最低でも半年〜数年の長さで見てください。
3. **「保有」の表** — いま持っている銘柄、株数、全体に占める割合、損益。現金が何%あるかも出ます。

「約定待ち」は、注文は出したが、まだ売買が成立していない分です。注文は次の取引日の始値で成立します。

## 日報の読み方（data/journal/）

日付ごとのファイルです。最初の1〜2文に、**今回は何を買った・売った・見送ったか**が書いてあります。続きには、見たニュース、判断の理由、見送った候補とその理由があります。

見るポイント:

- 買った理由は、あなたが納得できるか
- 「未確認」と書いてある事実は、あとで確かめたか（Claude は、確認できなかったことを断定せずに「未確認」と書くよう決められています）
- 1つのテーマ（例: AI 関連）に資金が偏っていないか

## 実際に売買するなら

このシミュレーションは、証券会社の口座にはつながっていません。日報に「注文した場合の入力例」（市場、銘柄名と銘柄コード、売買、株数）が書いてあります。**同じ売買を実際にやるかどうかは、あなたが決めます。** やるなら、その内容を証券会社のアプリに自分で入力してください。

シミュレーションの約定価格は「次の取引日の始値」を基にした概算です。実際の約定価格とは少し違います。

## 自動で動かす

### Windows

1. `register_task.ps1` を右クリックし、「PowerShell で実行」を選ぶ。または、ターミナルで次を打つ。

   ```
   .\register_task.ps1
   ```

   これで、毎朝7:30に1回分の運用が自動で動くようになります（時刻を変えるときは `.\register_task.ps1 -At 21:00`）。
2. パソコンが起動していなかった日は、次に起動したときに動きます。
3. 動いた記録は `logs/` フォルダに日付ごとに残ります。
4. やめるときは、ターミナルで次を打ちます。

   ```
   Unregister-ScheduledTask -TaskName "Claude資産運用" -Confirm:$false
   ```

### Mac / Linux

ターミナルで `crontab -e` を開き、次の1行を足します（パスは自分のものに置き換えます。毎朝7:30の例です）。

```
30 7 * * * /Users/あなたの名前/リポジトリ名/run_daily.sh
```

### 動かす頻度の目安

毎日でも、週1回でも動きます。**長期保有が前提なので、週1回でも十分**です。毎日動かすと、調べる分だけ Claude の利用量が増えます。初期のルールは「直近6日間で注文3件まで」なので、週1回の実行と相性がよい作りです。

### 自動で動かすときの注意

- 運用の記録は、`data/` と日報に残り、最後に Git のコミットになります。GitHub に自分のリポジトリを作っていれば、自動で push（＝送信）まで進みます。
- パソコンがスリープしていると動きません。確実に動かしたいときは、動かす時刻に電源が入っているようにしてください。
- 自動実行は、確認の質問に答える人がいないので、`.claude/settings.json` に書いた許可の範囲で動きます。この範囲を広げるときは、何を許可するのかをよく読んでからにしてください。

## 一時停止・解除

- **自動実行を止める**: 上の「やめるとき」のコマンドを実行する。
- **新規買いの自動停止**: 資産が最高値から30%（初期値）下がると、`sim.py` が新規の買いを止めます。解除できるのは人間だけで、ターミナルで `python sim.py resume` を打ちます。**Claude には打たせないでください**（打てないように設定してあります）。止まった理由を日報で読み、方針を見直してから解除してください。

## 最初からやり直す

`data/` フォルダの中の `state.json`、`pending.json`、`ledger.jsonl`、`history.csv`、`journal/` の中身を削除し、`REPORT.md` も削除してから、`data/watchlist.json` の「保有」に関する記述（`status` の行）も古くなるので、Claude に「保有状況を初期化後の状態に直して」と頼むか、中身を `{}` に戻します。そのあと、もう一度 `python sim.py init` を実行します。**以前の記録は消えるので、残したければ先に別の場所にコピーしてください**（フォルダごと `archive/` に移すと残せます）。
